# elliprof test plan

## Principles

* **The reference implementation is the unchanged original ELLIPROF Fortran.** Tests cover everything around it (inputs, preparation, validation, outputs, packaging), check fits against synthetic images with known answers, and guard against drift with stored baselines.
* **Exact where exactness is guaranteed, toleranced only where it isn't.**
  - Preparation (sky, mask) is bit-exact.
  - On one platform, the backend, the Python API and the Python CLI give byte-identical `.prf` files.
  - Between platforms, numerical tolerances apply, set from measured spreads.
* **Baselines are never regenerated by a test run.** Only `make update-baselines`, which is maintenance, writes them. Numerical changes show up as differences in `.prf`/`.reg`.
* **Normal tests stay inside ELLIPROF's safe range:** 2 ≤ NR ≤ 100, R0 ≥ 3 px.

## How to run

| Command | What it runs |
|---|---|
| `make check` | build, source hashes, unit + integration + regression (238 tests) |
| `make docker-test` | the same inside Ubuntu 24.04 |
| `pytest -c tests/packaging/pytest.ini tests/packaging` | 10 tests against an **installed** wheel |
| `make notebook-check` | executes the example notebook |

One test is skipped unless `ELLIPROF_SBF_DIR` points at masks written by the original software. It passed when last run with that data (all 1,047,550 pixels agree).

## Synthetic regression (`regression/test_synthetic.py`)

* **Cases:** circular, elliptical, rotated, off-centre, constant sky, 2-D sky, star without mask, star with mask, noisy, model. All are r^¼ galaxies, 200×200, with an explicit X0/Y0, stored in `tests/data/regression/`. The circular, elliptical, rotated, off-centre and model cases have no sky.
* **Truth limits** (contours with 5 ≤ Rmaj ≤ 0.8 R1), about 3–5× the measured recovery:

  | Quantity | Noise-free | Noisy |
  |---|---|---|
  | centre | 0.05 px | 0.5 px |
  | ellipticity | 0.015 | 0.02 |
  | PA | 0.5° | 2° |
  | I0 | 1% | 3% |
  | de Vaucouleurs Re/Ie | 3% | 5% |

* **Masked star:** the worst I0 error is < 1% and at least 3× smaller than without the mask.
* **Undefined angles:** PA is not checked for round isophotes (ellip < 0.02), and harmonic phases A3/A4 are compared only where I3/I4 > 0.005. Both thresholds are in `tolerances.json`.
* **Baselines:** byte-identical on the platform that made them. On other platforms they are compared with `tolerances.json`, which is still **provisional**: exceedances are reported as xfail with the measured value.
* **Measured spread** (`regression/spread/`):
  - Linux x86_64 and aarch64 are bit-identical to each other.
  - macOS arm64 vs Linux, well-conditioned cases: x0/y0 ≤ 3e-3 px, I0 ≤ 7e-6 relative, ellip ≤ 2e-4, alpha ≤ 0.015°.
  - The circular case is ill-conditioned (undefined PA).
  - **Proposed final tolerances:** x0/y0 0.03 px, I0 1e-4 relative, alpha 0.15°, ellip 2e-3, slope 1e-3, I3/I4 1e-3, A3/A4 1°. These are to be confirmed after macOS x86_64 and Windows are measured.

## Real data (`regression/test_u12517.py`)

UGC 12517 with its BITPIX=1 mask, `--sky 3246.0`, `X0=567 Y0=562`, `R0=9 R1=347 NR=23 NITER=10 RMSTAR`. Checks:
- the inputs load (1025×1022, 103,402 masked pixels);
- the fit completes with 23 contours;
- N_PRF = CSV rows = ellipses;
- the profile is plausible (I0 decreasing outward, centre within 3 px, ellip 0.05–0.4);
- the result is byte-identical to the baseline on the same platform.

## Packaging (`packaging/test_installed_wheel.py`)

Run against an installed wheel in a clean environment:
- the installed package is imported, and the backend lives inside it;
- no compiler is needed (`ELLIPROF_TEST_REQUIRE_NO_COMPILER=1` makes this strict);
- `--help`, `--version`, `--diagnostics`, `python -m elliprof`;
- an explicit centre with scalar sky; the centre is required; sky image + mask;
- the Python API is byte-identical to the CLI;
- spaces and non-ASCII characters in paths.

`tools/ci/check_backend_deps.py` must report that every library is bundled or part of the OS. The CMake-built backend reproduces the Makefile-built baselines byte for byte.

## Source integrity

`unit/test_source_hashes.py` checks the SHA-256 of the 9 original Fortran files and 4 include files against `tests/original_source_hashes.txt`, which is edited by hand only. `unit/test_build_config.py` checks that the Makefile and CMake use the same flags and sources, with no preprocessing, bounds checking or aggressive optimisation.
